4. eGFR BOOLEAN RECONCILIATION
Canonical eGFR is now Boolean in active Flutter metadata, both input models, production and mock answer validation, the fact schema, active rule routing, persistence checks and current-contract trace labels.
true = eGFR >=30 mL/min. false = eGFR <30 mL/min.
The clinician sees eGFR >=30 mL/min? with Yes/No, not a numeric text box. The server question uses the authorised full sentence.
Historical numeric values are not converted to threshold confirmations. Evaluation removes a historical number only from its temporary input map and asks for fresh clinician confirmation. Stored historical values are not rewritten by the migration. Input models return missing for an old numeric value.
Older numeric trace snapshots remain readable as historical evidence; they do not create a new current-contract fact.

5. P1 ELIGIBILITY IMPLEMENTATION
New active root P1_DEMOGRAPHIC_ELIGIBILITY uses a server-derived Boolean based on the protected source context. It is not an editable clinician answer. Client/clinician flags cannot override the protected source.
Accepted entry demographics: postmenopausal woman OR man older than 50. Male age 50 does not qualify. Missing profile sex, missing male age or missing/uncertain female menopause stops for information. Male menopause is not fabricated.
Structured minimalTraumaFracture choices: yes, no, not_sure. The active question is Did the fracture occur after a fall from standing height or less? Patient free text is not consumed as confirmation.
Structured fractureSite choices include separate hand, foot, face and ankle values and non-excluded sites such as hip, vertebral and leg. The old combined patient answer is neither split nor inferred.
Missing mechanism/site returns a question. Explicit Not sure returns an information-required review error. No or an excluded site returns an eligibility-not-met review error. These states contain no treatment actions and cannot save a completed recommendation. The Flutter case remains in progress so the clinician can correct an answer; the task does not create a new clinical-case status.
The new migration extends the protected context with an eligibility source snapshot, preserves actor/assignment/investigation checks, and preserves downstream invalidation. Current source changes reject stale evaluation saves and approvals. Withhold retains its existing clinician-controlled behavior.

6. P2 STRICT >12-MONTH CORRECTION
New canonical key: antiresorptiveTreatmentOver12Months.
true means current antiresorptive treatment for more than 12 months; false means 12 months or less.
Question: Has the patient used the current antiresorptive treatment for more than 12 months?
Flutter presents Yes/No. The rule consumes the new key. False takes the existing standard antiresorptive-options branch; true continues to adherence.
Old antiresorptiveTreatmentDuration answers are ignored during current evaluation, and attempts to save the retired key are rejected. Existing >=12 answers are not silently reinterpreted. No raw duration, medicine-history free text or patient report is converted into the clinician threshold confirmation.
Trace snapshots carry the contract version. Old saved duration traces are identified as historical, rather than relabelled with the new strict boundary.
